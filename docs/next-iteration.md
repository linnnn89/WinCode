# WinCode 效率与准确性迭代

更新：2026-10-08。本文是唯一的后续任务入口，只保留未完成工作。接手时核对当前分支、远端差异和工作区改动。待办包含尚未实施和验收未闭合的项目；当前接口以使用说明为准，尚未取得新的性能比较结果。

## 目标与下一步

优先提高一次任务得到正确结果的概率，再减少无效读取、模型往返和等待。不能靠忽略必要证据提高成功率，也不能靠少返回关键信息降低 token。

**C 的设置复选框实验仍待实际设置页。** 先确认具体控件与独立预期，再进入配对试验；当前没有性能比较结论，不一次实现整张路线表。

日常只读本文；调用客户端时查[使用说明](hybrid-readonly-orchestration.md)，定位实现时再查[架构](../WinCode-架构与数据流说明.md)。历史计划与过程日志已从工作树移除，需要追查时按 PR 或 Git 历史读取，不默认加载旧版全文。

## 需求依据

| 用户任务 | 已知事实或需求假设 | 优先处理 |
|---|---|---|
| “实际软件能否像测试窗口一样可靠使用” | 真实应用已有单候选／单控件证据，多候选和条件统计主要在夹具验证 | C：迁移一个真实任务 |
| “能不能少等、少读、少花 token” | 存在小样本记录，尚无代表性任务的稳定收益证据 | C 先测完整成本，再决定 D |
| “检查设置值、列表选择或另一层页面” | 合理但尚未确认频率的需求；当前展开编排最终只接受 toggle 状态 | 先收集具体目标，按一个类型扩展 |

表中后两项属于需求假设，不自动启动新功能或外部模型实验。其他无关节点是否造成误拒绝，须用具体场景复现后再决定改法。

## 借鉴与取舍

| 官方资料与成熟实现 | 可借鉴的做法 | 在本项目的应用判断 |
|---|---|---|
| [Playwright Locators](https://playwright.dev/docs/locators) | 逐步缩小定位范围，动作时重新解析目标，单目标操作保留唯一性检查 | 复用现有父路径与新鲜定位；不靠 first/nth 消除歧义，不保存跨请求 COM 元素 |
| [Playwright Actionability](https://playwright.dev/docs/actionability) | 不同操作检查不同前置条件 | 按“读取、统计、操作”判断必要字段；UIA 与浏览器机制不同，不直接移植浏览器等待或 force 行为 |
| [Anthropic 工具设计](https://www.anthropic.com/engineering/writing-tools-for-agents) | 依据真实任务评估，返回相关信息和可操作错误，避免无关上下文 | 优先改已有配方和 compact 输出；保留错误、范围及截断标识，不再增加通用工具目录 |
| [Anthropic Agent 评估](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | 区分能力探索和回归，用可验证结果评估任务 | C 同时核对业务结果和执行轨迹；允许不同合法调用路径，失败成本不能排除 |
| [Microsoft UIA 批量获取属性](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-cachingforclients) | 一次取得所需属性，减少逐属性跨进程调用；缓存需要刷新 | 仅当 D 证明属性读取是主要瓶颈时，评估单次请求内批量读取；不直接新增全局缓存 |

真实 issue 的适用边界：[FlaUI #357](https://github.com/FlaUI/FlaUI/issues/357) 中维护者复现了 ScrollViewer 子控件 IsOffscreen 不反映实际可见范围，说明可见性与语义状态不能混为一谈；[FlaUI #552](https://github.com/FlaUI/FlaUI/issues/552) 报告重启应用后属性不受支持，评论中的旧状态猜测没有形成已验证修复，不能据此改 WinCode 生命周期。属性不受支持也不能用 false 代替真实状态，见 [Microsoft 属性读取规则](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-propertiesforclients)。

[FlaUI #216](https://github.com/FlaUI/FlaUI/issues/216) 报告同 ID 的多个视图中 FindFirstDescendant 读到错误元素，报告者改用 FindAllDescendants 后关闭 issue。这里采纳的是“首个匹配不代表目标正确”的教训；本项目继续要求明确父范围内唯一匹配，不能用遍历顺序消除歧义。

资料于本次联网查阅。上表最后一列是针对 WinCode 的设计判断，外部成功经验不构成本地验证。无需为采纳这些原则升级 SDK、引入 Playwright、修改运行环境或增加服务。

## C．实际任务验收与效率基线

### 实验问题与范围

由 GPT-6.1 Sol、high 推理强度独立测试：当前未提交构建能否在 Steam 实际设置页面正确读取指定复选框，且配方相对原生读取是否减少调用方负担。测试者重新取得观察和预期，不沿用开发者的成功结论。这里比较两种客户端执行方式，不比较模型能力，不调用外部模型 API。

只使用用户已打开的 Steam。允许按实际观察到的唯一可操作控件打开设置和一个相关页签；导航属于准备阶段，至多 3 个语义动作，不更改设置、账号、下载或交易状态。无法通过已支持的语义动作到达时报告需用户打开的具体页面，不新增坐标、键盘或浏览器后端，不重启应用、改启动参数或扫描其他窗口。后台截图保持 backgroundOnly:true；不为取图恢复或激活窗口。

当前阻断：独立测试在商店首页未取得复选框案例；一次菜单 Invoke 虽被受理，约 33 秒后的读回未确认导航成功，不能排除菜单曾短暂出现。需用户手动打开相关设置页后重新准备；设置页的 UIA 兼容性仍未知。测试者不得用 WPF 夹具代替 Steam，也不把成功读取 Document 当作条件统计通过。

### 准备与独立预期

1. 记录实际分支、HEAD、dirty 状态；保存工作区 diff 和本轮涉及文件 SHA-256 到忽略目录。核对磁盘构建、delivery:verify、实际会话 buildId 与 Host inspectionVersion。测试包含本地未提交改动，不能只凭 HEAD 宣称版本相同；不切分支、不重建或修改被测实现。身份不匹配则报告阻断。
2. 只读接口说明和必要使用手册后开始黑盒测试。重新列出 Steam 窗口，明确 PID/HWND；只用一个当前构建的 WinCodeSession/CLI，会话前后核对身份。父任务和其他测试不得同时操作 UI；旧 MCP 连接不能代替该构建。
3. 从实际页面选 2–6 个相关复选框，尽量包含当前自然存在的 On、Off、禁用状态。先从清晰截图或用户明确陈述记录每个标签的预期，再将标签与唯一 AutomationId 对应；视觉无法确认的字段保持 unknown，不能复制配方输出作为预期。
4. 冻结窗口、scopePath、regionAutomationId、所选 IDs、可选 summaryAutomationId、预期和预算至 case.json。只有实际存在有业务意义的摘要开关时才测条件分支；没有摘要则仅测无条件统计，并将条件验收列为未覆盖。缺少稳定 ID、唯一公共父范围或独立预期时不进入计分试验，报告具体能力缺口，不更改产品或造假数据。

### 配对执行

| 路径 | 执行方式 |
|---|---|
| N：原生基线 | 通过同一会话调用标准 scoped inspect，单次读取必要区域并独立核对所选 IDs 与状态。若有摘要，先只读摘要，On 才读详情，Off 不读详情。不得人为拆成逐控件 N 次读取；不调用配方实现完成统计 |
| R：客户端配方 | 同一会话调用 readonlyUiRecipe(target, 'checkbox-audit', parameters) 或 CLI readonly-ui，读取完整 steps、findings、isError 和 scopeResult，不修改配方 |

同一冻结案例顺序为 N1 → R1 → R2 → N2（两对，交换先后）；每次重新读取，禁止复用前次结果冒充试验。初始准备和连接预热单列，两条路径均使用暖会话。同一组 query/tree 预算与总 deadline，默认每次 15 秒；原生多调用共享剩余 deadline，不能给每一步各 15 秒。预算若不足，只能在冻结案例前基于实际节点调整。

每次核对逐项身份、On/Off、isEnabled、checkedCount、unchecked、disabled；禁用且 On 仍计入数量。带摘要时同时核对 detailsRequired 和 Off 零详情读取。前后截图/独立读回若发现页面或状态变化，标记 affected，不进入相同状态的耗时比较，保留已花成本。不会为了补齐 On/Off 组合修改真实设置；未出现的分支明确未覆盖。

正例可执行后，额外做一次只读范围反例：在已观察路径后追加明确标注为测试用且本次观察不存在的随机父选择器，预期范围失败、无 findings、无整窗回退。真实布局若有同名旁支可检查歧义；没有则记未覆盖，不构造 Steam 控件。本轮不重跑全部夹具或完整回归。

### 记录与判断

| 测量项 | 口径 |
|---|---|
| 正确性 | 每个已启动 trial 单独记 pass/fail/affected；未进入试验记 blocked 或 unsupported。N、R 分别给首次成功数/尝试数，记录误报成功、误拒绝、越界及未覆盖项；不得删除失败重算分母 |
| 调用成本 | 分开统计调用方请求、内部 MCP 读取、动作、Helper 启动、结果文件读取和实际模型往返。两路径可能有相同 MCP 次数；一次配方入口不等于一次原生读取 |
| 字节与时间 | 记录原始文本块 UTF-8 字节、配方最终文本字节、图片字节及每次墙钟耗时；内部证据、最终输出不要重复相加当模型输入。准备/冷启动、试验、失败/纠错、人工等待、清理分别列账；完整 token usage 缺失就写 unknown |
| 干扰与清理 | 记录前台变化是否实际观察、设置前后状态、实际动作；close 后验证自有 Gateway/Helper/测试进程退出，保留 Steam。未知项不能填“零干扰” |

发现结果与独立预期不一致、未经请求的动作、目标改变或清理失败，即停止后续性能试验并保留证据；不边改实现边验收。AUDIT_BUSY 或外部状态变化只有原因已消失且仍在预算内才可重新准备，原失败不删除；超时不自动重放。总量最多 20 次原生 UI 请求（含发现、导航、取图、失败），主动操作时间最多 20 分钟；达到限制就报告实际进展，不继续扩张。

仅在四次正例、范围反例、状态保持和清理都成立时，判定该案例通过。无摘要时只能判定无条件案例通过，C 的条件分支仍待验。这是一项适用性与粗略成本试验，不给 P95、统计显著性或稳定收益百分比；发现没有收益时保留更简单的原生路径。实现细节与原始返回只在解释失败时读取，测试者不修改源码、安装 Skill 或本计划。

产物集中写到 test-tmp/c-steam-independent-<时间>/：case.json、包含所有尝试的 trials.jsonl、完整原始回执/必要截图、一个 report.md。报告只写版本、任务与独立预期、N/R 逐次结果、成本、失败与限制、清理证据，以及至多 3 条有证据支持的最小建议。个人内容只留本地，公开摘要去标识。父任务审阅后只将仍未解决的问题保留在本文，不新增历史工作日志。

## D．测量后才决定的优化

| 观察到的实际瓶颈／需求 | 最小候选改动 | 进入条件与边界 |
|---|---|---|
| 原生逐属性读取占主要时间 | UiTreeReader 内按需批量取得属性／状态 | 先分离 Host 启动、定位、属性读取耗时；核对当前 FlaUI API、取消与故障语义。只在请求内用缓存，动作后刷新 |
| 首次发现被无关 Group 的未知状态阻断 | 区分“列出部分候选”和“足以安全执行唯一目标” | 先有误拒绝复现；保留缺口并让调用方明确选择，不能把部分搜索的单个候选当全局唯一 |
| 多层区域迫使 AI 重复拼装已观察路径 | 返回更易使用的局部候选／路径建议 | 路径来自实际观察，下一请求重新验证；先优化反馈，再决定是否需要短路径执行 |
| 真实任务要读选择项或文本数值 | 在现有原生能力上增加一种明确结果读取 | 先定义控件、字段与独立预期；不默认读取输入内容，不同时扩展所有控件类型 |
| 同名按钮／输入框确实妨碍已授权操作 | 给 click/type 补可选父范围 | 独立任务验收：范围贯穿、旧 Host 拒绝、旁支不受影响、结果未知不重放 |

不预建递归导航引擎、累计配额／授权状态机、全局 COM 缓存或新服务。异步显示问题先复现，再评估有截止时间的只读等待；不增加固定 sleep，不自动重试未知结果的写动作。

## 执行与维护

每次选一个工作包，先查当前分支、真实源码和相关测试。优先最小复现／相关检查；涉及 UI 的改动必须走实际入口。普通局部任务至多新增 3 项自动化测试；完整回归按影响运行一次，失败后遵守仓库的诊断与重试限制。不得因本文存在待验项就自动安装依赖、运行外部付费实验或扩展任务。

任务完成后从本文删除对应任务，把用户可见变化写入 CHANGELOG、验证及失败写入该次 PR；仅保留仍成立的限制。更新使用说明中实际发生变化的契约，不追加“第几轮”流水账，不另建重复路线图。文档改动检查链接、命令、字段和新旧能力边界；文档检查不替代运行时验收。
