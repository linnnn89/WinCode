# WinCode 效率与准确性迭代计划

更新：2026-10-10。本文作为未完成工作的唯一跟踪入口，仅保留当前已知限制、真实应用验收条件及有证据触发的候选优化。当前已上线接口见 [客户端 UI 工作流](hybrid-readonly-orchestration.md)，实现结构见 [架构与数据流说明](../WinCode-架构与数据流说明.md)，已完成变更见 [CHANGELOG](../CHANGELOG.md)。

## 1. 当前状态与优先事项

- `checkbox-audit` 已支持精确 `name + CheckBox` 选择器并兼容原有 `AutomationId` 模式，单元回归与核心检查均已通过。客户端混合流程保持显式调用，不会自动请求外部模型或更改客户端默认配置。
- **真实非 WPF 应用验收尚未闭合**：在某基于 CEF 的设置页面测试中，原生 UIA 未能稳定暴露业务复选框控件（对照 Control/Raw View、MSAA 接口读取及一次授权重启后仍未恢复可验证控件集），因此尚未进入原生基线与客户端配方的配对计时对比。目前不能宣称该类内嵌 Web 界面的适配通过或具备稳定性能收益。
- **下一步重点**：优先定位目标应用的原生 UIA 暴露缺口；仅在获得新线索支持具体假设时继续诊断，避免无意义的重复重启或放宽完整性校验（[CEF 可访问性接口文档](https://github.com/chromiumembedded/cef/blob/6478/include/cef_browser.h#L839-L865) 仅作机制参考，尚不能直接认定为目标应用的根因）。

## 2. 真实应用配对验收规程

### 准备与前置条件

- 仅在用户明确授权的目标应用与页面上测试，按实际观察到的唯一语义控件导航，不修改用户的业务配置。如需重启目标应用或调整其启动参数，须另行获得授权。
- 测试前核对当前源码、磁盘交付清单与会话连接身份，同一轮测试复用同一个会话并冻结实现代码。
- 选取 2–6 个实际存在的复选框，基于独立截图或用户确认建立预期结果（无法独立确认的字段记为 `unknown`，不得拿工具自身输出倒推预期）。
- 缺少唯一控件身份、共同父范围、独立预期或完整原生观察时立即停止准备，记为 `blocked` / `unsupported`。

### 配对执行与判定标准

| 对照路径 | 执行方法 |
| --- | --- |
| **N（原生基线）** | 在同一会话中执行单次带范围的 `wincode_ui_inspect` 读取目标区域并核对控件（若页面有总开关则先读总开关，`Off` 时跳过详情；不人为拆成逐控件多次请求）。 |
| **R（客户端配方）** | 调用 `readonlyUiRecipe` 或 CLI `readonly-ui`，核查完整的 `steps`、`findings`、`isError` 与 `scopeResult`。 |

1. 按 **N1 → R1 → R2 → N2** 交错顺序执行（默认单次预算 15 秒，准备与预热耗时单独记录）。
2. 逐项核对控件身份、`On`/`Off`、`isEnabled`、`checkedCount`、`unchecked`、`disabled`（禁用但勾选 `On` 的控件仍计入 `checkedCount`；总开关为 `Off` 时详情读取次数须为 0）。
3. 四次正例完成后，执行一次**缺失父范围反例**，确认返回范围失败、无成功 `findings` 且未回退到整窗扫描；最后确认目标页面状态未变且自有辅助进程已全部退出。以上全部满足方为通过。

### 成本记录与止损边界

- 如实保留所有尝试、失败与等待记录，分别统计请求次数、原生 Helper 启动次数、结果文件读取、墙钟耗时与输出字节数（两对样本仅用于评估可用性与大致开销，不推断 P95 或普适提速比例）。
- 单轮测试上限为 20 次原生 UI 请求或 20 分钟主动操作；一旦出现结果不符、非预期界面副作用或清理失败立即停止，超时不自动重放。
- 本地窗口截图、机器路径与原始诊断日志仅保存在被 Git 忽略的 `test-tmp/` 下，严禁提交入库或上传至公开 PR。

## 3. 按需触发的候选优化（先测量后动手）

| 待确认瓶颈或真实需求 | 最小候选方案与准入前提 |
| --- | --- |
| 原生逐属性读取占主要耗时 | 先拆分 Helper 启动、树定位与属性读取耗时；确认瓶颈后再评估单请求内批量属性读取，不引入跨请求全局 COM 缓存。 |
| 首次发现因无关兄弟节点属性异常被误拒 | 先捕获真实应用的误拒复现样本；不得将未完成搜索的单一候选当作全局唯一。 |
| 深层页面导致手动拼装长路径繁琐 | 候选路径必须源自上一次真实观察并在下次请求重新校验；不预先构建自动递归导航引擎。 |
| 真实场景需批量核对下拉框或文本值 | 先明确目标控件类型、所需 UIA 模式与独立验证标准，每次只按一种明确结果类型扩展。 |
| 同名按钮/输入框需要限定父范围操作 | 单独设计并验收 `click`/`type` 的 `scopePath` 支持、旧版本 Host 拒绝及未知动作结果不重放策略。 |

## 4. 其他跟踪事项

| 事项 | 当前状态与跟进条件 |
| --- | --- |
| Roslyn 会话刷新偶发缺失引用 | 历史测试曾偶发一次刷新后引用缺失（已保留完整错误捕获，后续未再复现）。若再次出现，先采集底层诊断信息，不放宽快照有效性校验。 |
| Roslyn 源生成器支持 | `WinCode.Code.Host` 当前默认排除分析器与源生成器；待有明确项目需求时，再评估受控加载与快照失效机制。 |
| 客户端冷启动零进程核验 | 待正常重启客户端宿主时，顺便核验按需模式下首次调用前确实无后台 `WinCode` 进程。 |
| `REC` 提示浮层偶发初始化失败 | 曾偶发 `Recording indicator could not be displayed`；复现时先采集底层 Win32/GDI 异常与初始化耗时，不得绕过提示浮层或盲目重试。 |
| 特殊运行环境兼容性 | 长时间驻留、复杂动态 MSBuild targets、多显示器非标准 DPI、高权限窗口及 Explorer 重启后托盘恢复，按实际触发场景专项验证。 |
| 版本发布状态 | 仓库代码合并、本机交付构建、Skill 同步与客户端重连需分别核实；当前尚未发布正式 GitHub Release。 |
